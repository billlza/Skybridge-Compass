# 共享观看与输入权

架构决策与信任边界见 [ADR-0002：远程控制的身份授权与会话所有权](ADR-0002-Remote-Control-Authority-and-Sessions.md)；传输适配继续遵循 [ADR-0001](ADR-0001-SkyBridge-Core-Transport-Matrix.md)。

一个控制端可保留最多两台主机的连接，连接中也占容量。多个观看端连接同一主机时，观看许可与输入权分别管理：每条连接都须由被控端批准，只有一个观看端可以发送键鼠与剪贴板操作。首次批准可授予输入权，其他已批准连接为观察者；观察者通过被控端的“交接输入权”操作获得控制。断开当前控制端不会自动把输入权分配给剩余观察者。

## 会话与资源边界

- macOS LAN 入站由 `RemoteControlInboundSessionCoordinator` 按确切 socket 和代次持有独立的既有 `RemoteControlManager`。握手、待批准与已连接会话共用两条容量；准入名额保留到会话结束。监听器重建保留现有会话，显式停止则关闭所有确切连接。
- 各会话拥有自己的采集、编码、解码和发送状态。坐标映射按输入所有者保存；会话退出只能清理自己的映射和剪贴板。某台采集重启时，另一台存在的映射不能阻止原所有者释放已按下的键或鼠标。
- `RemoteControlSecurityNoticeCenter` 负责可见批准、会话列表与完整交接事务；`RemoteControlHostAccessCoordinator` 管理授权版本及唯一输入权。HID 注入仍由原输入生命周期协调器执行。
- 交接先撤销旧授权、释放旧输入，再通知观察状态和新授权。整个事务包含失败清理；断开参与方不能让旧错误处理关闭后来成功获权的会话。未收到任何新授权的观察者保持连接。无法释放输入或授权通知投递不确定时显式失败，不恢复旧授权。
- 控制端每个输入队列固定一个授权代次。撤权会丢弃未发送事件；已经开始的发送保留原期限，不能通过频繁交接累积无界挂起任务。本地切换主机仍先完成原有输入的逆序释放，再改变媒体焦点。

两路独立采集复用了现有协议与媒体引擎，资源消耗仍随连接数增加。本实现没有共享编码广播层，不声称恒定成本或已达到多主机性能目标。macOS 后台主机沿用 2 FPS、受限尺寸和关闭音频的预算；移动端后台暂停媒体并等待确切配置确认。

## 协议

所有字段位于既有认证加密信封内，不更换身份、密钥派生或握手协议。

1. 首个 `streamConfiguration` 以 `remoteControlAccessVersion: 1` 声明共享观看与输入租约能力。这个选择固定于该认证会话，后续配置不能改成其他版本或移除它。
2. 主机首个 `streamConfigurationAck` 可包含 `controlAccess`：`version` 为 1、`revision` 为正整数且不超过 `Int64.max`、`role` 为 `controller` 或 `observer`。控制者必须包含非空 UUID `lease`，观察者不得包含 lease。
3. 后续本地交接通过主机到观看端的独立 `controlAccess` 消息更新授权。它只在完成 managed ACK 后合法，与媒体配置事务解耦，避免画质重配的迟到 ACK 覆盖交接结果。
4. 每次新的输入授权使用新 lease。输入信封的 `inputControlLease` 必须与当前确切连接的授权相等。消息入队时固定 lease；不能在真正发送时给旧事件补上新 lease。
5. 授权 revision 较旧的合法消息不覆盖当前状态；同 revision 内容冲突、版本非法或降级都是协议错误。观看端不能向主机发行授权消息。
6. 首个 ACK 未包含 `controlAccess` 时，客户端使用原有独占控制合约。支持新协议的主机不会让 legacy 与共享观看会话混在一起。legacy 的媒体暂停与恢复仍需按原配置事务确认，不能把“没有输入租约扩展”误判为“不需要恢复视频”。

## 平台能力

| 平台 | 控制端 | 被控端与限制 |
| --- | --- | --- |
| macOS | 两条独立 LAN 会话，单一输入和音频焦点 | 两条兼容的 LAN 观看会话；本机批准并交接输入权 |
| iOS / iPadOS | 独立 LAN 工作区；原有唯一 WebRTC 会话占同一两主机预算；相机为独立只读入口 | 不具备系统级受控管线，不作为被控主机广告或列入双主机验收 |
| Android | 两条 LAN 会话，明确暂停／恢复；观察者不接收输入操作 | 当前 LAN 宿主没有完整产品传输与启动入口，不宣称已支持被控；LAN 音频和剪贴板仍不可用 |
| Windows | 当前控制端能力必须以实际媒体与输入运行时为准 | 独立 LAN 被控会话与本机授权／交接；原生构建、启动及跨端并发验收单独核对 |

当前 WebRTC 宿主路径仍使用独占授权。它不能与共享 LAN 观看会话同时取得主机输入权。这里的共享观看不代表多个远端拥有独立的本机桌面，也不提供同时混合多套键鼠输入。

## 验证边界

行为回归包括容量预留、精确会话退休、跨授权队列、交接期间断开、释放失败、同一设备重新连接、配置重配、旧 revision、加密权限通知、剪贴板撤权和后台恢复。原生界面渲染使用测试会话，只证明界面布局；设备上执行 XCTest 也不能替代网络画面与键鼠验收。

发布前须完成两种真实拓扑：一个控制端连接两台被控电脑；两个控制端连接一台被控电脑。检查首帧、焦点／授权交接、长按与拖拽释放、断网隔离、声音归属、窗口关闭，并测量 CPU、GPU、内存、带宽及切换延迟。旧版宿主、Windows 原生界面和移动端实际安装包必须分别验证，不以一端的编译结果代替另一端能力。
